## 轨B：官方 Depth-Anything-V2（主模型）

**资产获取**（历次尝试中最优路径）：
- 前会话从 GitHub 第三方仓库 rydersd/ill-tool 直取官方 **DAV2-Small INT8**（27.26MB，sha256_8=01aa7a23）——绕开被墙的 HF/LFS
- 第 4 次沙箱重置后凭 GitHub 远端完整恢复（push 策略的价值实证）

**INT8 → 浏览器兼容**（本轮核心攻关）：
- 问题：INT8 图使用 ConvInteger/MatMulInteger（动态量化 QOperator），ORT-Web 的 webgpu/wasm EP 均无实现，会话创建直接失败
- 方案：`scripts/dequant_dav2.py` 图重写——31 个 ConvInteger→Conv、48 个 MatMulInteger→MatMul
- **关键陷阱**：首版把权重 scale 烘进了反量化权重，而图下游本就有 `Mul(x_scale·w_scale)` 补偿节点 → 双重缩放，输出坍缩为常数 0.089。通过插中间输出对比 old/new 逐层定位后修正（只做零点校正，scale 留给下游）
- **验证**：随机输入 392² 下 old vs new **maxdiff=0.00e+00（逐位一致）**，产出 `depth-anything-v2-small-web.onnx`（99.3MB）
- 预处理：`pixel_values` 输入 + ImageNet 归一化（mean/std），H/W 为 14 的倍数（392）

**浏览器实测**（puppeteer，2核 SwiftShader）：
| 项 | 结果 |
|---|---|
| 会话加载 | ✅ wasm，~4.6s（99MB + 编译） |
| 单帧估计 392² | ✅ 3.4-5.4s（沙箱 CPU；用户端 WebGPU 预期 <1s） |
| 深度值参与推理 | ✅ 11/11 目标全部拿到相对深度（均值 0.555） |
| turbo 伪彩叠加 | ✅ 右下角小窗（近蓝远红）+「深度 Xms · 近→远」标签 |

## 工程加固（本轮沉淀）

1. **推理期 WebGPU→WASM 降级**：WebGPU 会话可能在加载期正常创建、推理期才暴露 `createBuffer too large`（SwiftShader 实测）；inference.js/depth.js 均加 GPU 错误识别→重建 wasm 会话重试一次
